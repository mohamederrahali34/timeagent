# TimeAgent v0.2 architecture spike

## Observation boundary

The Node.js parent can observe the lifecycle and exit result of the top-level process it spawns. It does not receive executable names or argument arrays for arbitrary descendant processes. Running `timeagent run codex` therefore does not, by itself, reveal commands launched internally by Codex.

## Options considered

| Approach | Windows | macOS/Linux | Pre-execution block | Reliability and cost |
| --- | --- | --- | --- | --- |
| Explicit `PATH` proxies | Yes, `.cmd` shims | Yes, executable shell shims | Yes, for intercepted names | Small and portable; bypassable by absolute paths, changed `PATH`, built-ins, aliases, renamed or unlisted tools |
| Shell wrapper | Shell-specific | Shell-specific | Only inside that shell | Does not cover direct native process launches and requires fragile shell parsing |
| Descendant process observation | WMI/ETW or native APIs | `/proc`, `ps`, or native APIs | Not reliably | OS-specific, race-prone for short processes, primarily post-execution observation |
| Agent-specific hooks | Depends on agent | Depends on agent | Potentially | Semantically strong but not generic and tied to agent capabilities and versions |
| OS process tracing | ETW/security APIs | audit/eBPF/Endpoint Security | Only with much stronger enforcement | High complexity, often privileged, and unsuitable for this no-daemon prototype |

The v0.2 experiment selects explicit `PATH` proxies because they are the smallest mechanism that can make a decision before a known command executes on all target platform families. They are an awareness and policy aid, not a security boundary.

## SQLite feasibility

The filesystem checkpoint can copy a closed, single-file SQLite database, but raw copying is not guaranteed to represent a transactionally consistent database while connections are open. WAL mode also involves the database, `-wal`, and `-shm` files whose states must be coordinated. A useful SQLite adapter would need to use SQLite's online backup API (or an equivalent database-native operation) before the child action, validate completion, and restore only when connections are safely closed.

Merely labeling the existing file copy as a SQLite backup would add no correctness. No SQLite adapter is implemented in v0.2; it should remain separate until a transactionally consistent backup and tested restore protocol are available.
